## 1. Зачем боту быть первой линией

Клиенты GEO-маркетинга приходят не из поисковой строки, а из ответов нейросетей и мессенджеров. Первый контакт лаборатории должен работать круглосуточно и без ожидания — иначе часть AI-лидов уходит, пока основатель занят. Нужен был бот-лаборант, который делает три работы сразу: прогоняет сайт по технической части, отвечает на вопросы из базы знаний и принимает заявки. Бренд, который продаёт GEO-автоматизацию, обязан первым показывать собственную автоматизацию: прежде чем продавать, автоматизировали свою первую линию.

## 2. Тех-проверка: 10 приборов и вердикты

Гость отправляет боту адрес — и за считанные секунды получает отчёт технической проверки. Десять приборов, часть — с градацией «нет / наполовину / полностью»:

1. HTTPS — работает ли защищённое соединение.
2. robots.txt — пуст ли файл для краулеров и AI-агентов.
3. sitemap.xml — есть ли карта сайта по стандартному адресу.
4. llms.txt (AI-паспорт) — описан ли сайт для нейросетей машиночитаемо.
5. Meta title — есть ли заголовок страницы.
6. Meta description — заполнено ли описание или пустое (наполовину).
7. OG-теги — готов ли сайт к превью в соцсетях и мессенджерах.
8. Schema.org — есть ли разметка структурированных данных.
9. Canonical — указан ли канонический адрес страницы.
10. Заголовок H1 — есть ли главный заголовок.

Отдельный прибор — скорость ответа сервера: не дольше 10 секунд, иначе наполовину. Сумма приборов даёт вердикт лаборатории: 9–10 — зелёная зона, 6–8 — точки роста, ниже 6 — зона слепоты: «нейросети вас почти не видят». Лимит 3 проверки в день на человека — защита от износа.

## 3. База знаний без языковой модели

Бот отвечает только тем, что подтверждено материалами лаборатории. Шесть готовых тем: услуги и цены, «цифровой призрак», что такое GEO, как проходит аудит, о лаборатории, бесплатный мини-аудит. Плюс свободный вопрос — поиск по llms-full.txt, машиночитаемой базе знаний лаборатории. Если ответа в базе нет, бот честно отвечает «не буду выдумывать». Галлюцинации исключены архитектурой, а не обещанием.

## 4. Приём заявок: каждая заявка — AI-лид

Бот задаёт три вопроса: сайт или сфера, что болит, контакт. Заявка уходит в личку основателя с пометкой источника и дублируется на почту — почтовый дубль гарантирует, что заявка не потеряется даже при сбое Telegram. К моменту первого разговора у лаборатории уже есть сайт, боль и контакт — это и есть AI-лид: лид, собранный цифровой средой до первого сообщения человека.

## 5. Как это сделано: стек

- Платформа: Cloudflare Worker — бесплатный уровень, без серверов.
- Интерфейс: Telegram Bot API (бот-лаборант @geo_upgrade_labbot).
- База данных: архитектура без БД — база знаний это файлы llms.txt / llms-full.txt на сайте.
- Дубль заявок: Formspree — почтовая копия каждой заявки.
- Разработка: Cloudflare Dashboard + веб-интерфейс GitHub.
- Аналитика: Яндекс Метрика (страница контактов).

Бюджет инфраструктуры — ноль рублей.

## 6. Результат и что дальше

- Круглосуточная первая линия: бот встречает гостя, отвечает по базе знаний, проводит тех-проверку и собирает заявки.
- Тех-проверка за секунды: первичная картина технической готовности сайта — 10 приборов, честный отчёт с вердиктом.
- База знаний без галлюцинаций: ответы только из подтверждённых материалов лаборатории.
- Воронка AI-лидов в одну сессию: тех-проверка → вердикт → предложение полного аудита → заявка в личку основателя.
- Ноль расходов на инфраструктуру: бесплатный уровень Cloudflare, поиск без языковой модели.
- Появление бота анонсировано в соцсетях, карточка лаборанта опубликована на TenChat.
- Следующий этап — мини-аудит AI-видимости силами бота: первичный замер видимости бренда в нейросетях с дублированием результата основателю.
